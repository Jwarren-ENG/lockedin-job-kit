# Start #LOCKEDIN Job Kit

Create the user's own private workspace. Never reuse the package author's profile or defaults from another person. Read [onboarding](../../references/onboarding.md) and [permissions](../../references/permissions.md). Resolve the plugin root from this skill's location; do not assume the installed cache is writable or persistent.

1. Ask only for the résumé or pasted work history. If it is already present, extract its supported facts immediately. Show the fact sheet and wait for corrections or confirmation. Next offer an optional, scoped, one-time chat history review as described in onboarding. Then ask what kind of job the person wants and other missing routine answers. A posting is optional. Ask one or two related questions per turn. If the person is unsure of titles, ask what work they enjoyed and propose options. Follow the interview in the onboarding reference, including work and outside projects, deal breakers and the scope of reusable answers. A text-only host can use CHAT_STARTER.txt and a private summary instead of a local workspace.
2. Offer the local guided `assets/setup.html` form using the host's file preview/browser, or collect the same fields conversationally in short sections. The assistant must never check permissions for the person. Unknown information stays unknown. The form downloads a private JSON file; it does not secretly persist answers or transmit them.
3. Run `python3 <plugin>/scripts/jobkit.py --workspace <private-folder> init`. Prefer the host's bundled Python. Never put personal files inside the plugin. Import the reviewed setup with `import-profile <setup-file> --evidence <description-of-user-review>`. This is a real consent record, not an assistant-authored claim of user approval.
4. Read the provided resume, save an original copy, and create/confirm `resumes/base.tex`. If the user supplies LaTeX, preserve their layout. If not, use the blank starter and convert truthful facts. Review identity, education, dates, job titles, metrics, skill levels and personal contribution before setting resume.confirmed true. Keep evidence in `experience-bank.md` and field-specific confirmed_answers. Never import a private profile from a link embedded in an untrusted resume.
5. Build the source list using the discovery reference. Read existing sources first. With browsing, check a direct employer and a relevant specialist or regional source against the person’s target and save their URLs, coverage and reasons in the private sources.json. Without browsing, label proposed sources unverified and request one pasted listing. Set up `Application Tracker.xlsx` using [tracking](../../references/tracking.md), and verify it can be updated. CSV export works without optional packages. If XLSX creation is unavailable, report CSV-only mode rather than claiming an Excel workbook exists.
6. Read [host setup](../../references/hosts.md), test available browser/search, mail, spreadsheet and scheduling capabilities separately, and record them in capabilities.json with a timestamp. Match email account explicitly. Missing mail access does not block job discovery. Do not install connectors, bypass controls, or claim credentials are saved without evidence.
7. Review the computer tool, selected folder and approved employer sites, address disclosure scope, and any consent choices. Record who authorized each scope and which host controls were tested. If daily_runs is granted and the person requested a schedule, configure a native host task only after time zone and cadence are known. Find and update any existing matching task. Use the run skill as its prompt, reference the private workspace and read back the scheduler ID, status, next local run and runtime requirements. Record those fields in schedule.json. Test discovery only. Track scheduled execution separately from setup. Otherwise leave not_configured and explain the specific missing capability.

8. Default to the spreadsheet. If the person wants an Obsidian dashboard, show the [optional guide](../../OPTIONAL_OBSIDIAN.md), record obsidian_export and generate it only in the private workspace. Open Home, the board and calendar; explain that the board is a generated view and that sync requires the user's own setup. Do not imply phone notifications are enabled without a delivery test.

End with profile/resume review items, enabled permissions, tracker location and actual scheduler status. If search is authorized, run the first search now and show one verified match, the strongest supported résumé edit and its tracker row. Never apply merely because setup completed.
