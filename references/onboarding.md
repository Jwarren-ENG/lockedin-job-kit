# Onboarding

Follow this order for every first run.

1. Request only the résumé (or pasted text/work history) and wait. With an attachment already provided, read it immediately.
2. Extract all supported material facts, preserve exact wording and dates where it matters, and show a grouped fact sheet. Identify uncertainty without guessing. Wait for “confirmed” or corrections. Repeat the changed lines until the user agrees.
3. Offer **Skip**, **Paste an excerpt**, or **Read conversations I choose**. Explain the purpose before accessing history. Ask the user to name or select the app and exact chats. Search or open only the selected conversations with a supported host tool. A project membership, available connector or installation is not permission. Never search broadly for candidate conversations before consent. If selection is unavailable, accept an excerpt. Present any new facts individually with a short source reference for accept, edit or discard. Save only approved facts with private-storage permission. After completing or ending this review, use the permissions command with {"grants":{"read_chat_history":false}} and record that the setup-only review ended; if revoked earlier, stop immediately. Never include raw chat text or private conversation links in applications. Do not collect history in recurring runs.
4. Ask for missing routine answers only now. Group questions by topic, offer simple options and a free-text answer, and let the user skip, go back, pause or review. A one-line progress cue is enough. Retain the last confirmed step privately only if the user chose to save it. Group any outstanding questions before requesting automation permissions.


Use short conversational sections or the local setup form. Never make users retype facts already supplied; present extracted resume facts for confirmation. Do not silently opt a new person into the package author's preferences.

Collect: legal/preferred name, application email, phone, current and permanent address, LinkedIn/GitHub/portfolio; education, graduation and optional GPA; exact job titles/dates, contributions and supported metrics; projects and skills with proficiency; work authorization by country, sponsorship, availability, internship hours, travel/relocation, languages, and clearance only where relevant. Do not collect SSNs, government ID numbers, banking details or passwords.

Ask desired roles, locations, onsite/hybrid/remote, seniority and employment types; base salary floor with currency and hourly/annual basis; excluded employers and industries; target start dates and constraints. Unknown salary is not zero. Build the private source list after learning the target. Ask about work they enjoy if they have no title in mind. Record salary floor separately from preferred salary and when a range qualifies.

For the experience interview, pick one project at a time. Who had the problem? How did the applicant recognize it, what did they try, what got unexpectedly difficult, what did they personally decide, and who else helped? How was the work used, what outcome was measured, and what could they show or explain? Offer the same prompts for volunteering, school, family responsibilities, hobbies, side projects or independent learning. Ask what must stay confidential. Read back a proposed bullet, label estimates, and save only confirmed wording and evidence in the private experience bank. A simple accurate result beats an invented number.

Ask what to save and what to share. Distinguish the current and permanent address from the preferred location. Review the form’s private profile.scope_notes for computer and address scope. Record address type, purpose, allowed recipients and confirmation in the private confirmed answers. If a grant has no usable scope, ask once before using it. Explain how to select a private folder, enable only the chosen browser and account, and configure a password manager through the host. Help the user pick the narrow remembered setting if available. A chat that cannot use these tools can still interview and draft.

Optional race/ethnicity, gender, veteran, disability, orientation and transgender answers live only in demographics.json with explicit save permission. Do not ask every optional question unless the person wants reusable demographics or a matching form requires clarification. Never conflate Hispanic ethnicity with mutually exclusive race options. Match the actual question and let users decline disclosure.

Save exact recurring answers as objects with question, answer, source, confirmed_at and scope (global, employer, country or application). For example, an employer-specific conflict of interest answer cannot become a universal No. Attach source references for resume metrics. Preserve the original resume, all submitted variants and an edit history. Mark imported facts unconfirmed until reviewed.

On settings changes, show the changed categories and scope, then record the person's actual instruction/action and timestamp. Re-importing the setup changes permissions; an assistant must never manufacture confirmation. Turning off daily_runs requires pausing the actual host task too. Plain local files are not encrypted; choose a private folder and the host's appropriate data settings. The plugin adds no telemetry, but content the host reads remains subject to that host's processing policies.
